# Design decisions

Key design decisions in mcpgate, each with the reasoning and what it would cost if it turned out wrong.

- target the official `mcp` Python SDK 2.3.x (v2 API: `mcp.Client`, low-level `Server(on_list_tools=..., on_call_tool=...)`, `TokenVerifier`) and pin `<2.4` — the gateway should sit on the official SDK and v2 is current; v2 serves both the 2025-11-25 handshake era and the 2026-07-28 stateless era from one server object — an SDK minor bump may move provisional APIs (the SDK marks middleware/context as provisional), so the pin must be raised deliberately.
- build the gateway on the SDK's low-level `Server` with `on_list_tools`/`on_call_tool` handlers, not `MCPServer` (FastMCP) — the gateway forwards arbitrary upstream schemas verbatim and needs per-request identity, which decorator-registered tools cannot express — more code than a FastMCP proxy, and low-level handler signatures can shift between SDK minors.
- validate JWTs against a local JWKS *file* only, never fetch a JWKS URL — the design calls for local JWKS only; no network on the request path removes SSRF/JWKS-poisoning and keeps tests deterministic; key rotation is a file reload on unknown `kid` (rate limited) — operators must ship the JWKS file themselves; no token introspection, so revoked-but-unexpired tokens are accepted until `exp`.
- allow only asymmetric JWT algorithms (RS*/PS*/ES*/EdDSA) and reject `none`/HS* at config-load time — kills algorithm confusion at the source — deployments that use shared-secret tokens cannot use mcpgate without a change.
- audience binding uses the gateway's resource URL (`listen.public_url`, else listen address + path) and the SDK middleware's own resource check is disabled (`validate_token_resource=False`) in favour of the verifier's `aud` check — one place enforces RFC 8707 binding with a precise audited reason — behind a proxy, a missing `public_url` makes every token fail with `wrong_audience`.
- namespace as `<upstream>__<tool>` with upstream names restricted to `[a-z][a-z0-9-]*` — many model APIs reject `.`/`/` in function names and the restriction makes splitting unambiguous so cross-server shadowing is impossible — tool names get longer; names past 128 chars are refused, not truncated.
- unknown and forbidden tools return the identical JSON-RPC error; later-stage denials (quarantine, rate limit, invalid args, upstream down) return `isError` results — no enumeration oracle, and LLM agents recover from `isError` observations better than from protocol errors — clients cannot tell "typo" from "forbidden" without the operator's audit log.
- pin fingerprint covers name, title, description, inputSchema, outputSchema, annotations; excludes `_meta`, `icons`, `execution` — those are what the model reads; the excluded fields vary between protocol eras or carry server bookkeeping — a rug pull hidden purely in `_meta` (which some clients may surface) goes unnoticed.
- quarantine is derived at lookup time (observed digest != pinned digest) instead of being a stored flag; approvals are picked up from the pin store's mtime — reverting upstreams self-heal and CLI approval needs no restart or IPC — a pin store on a filesystem with coarse mtimes could delay an approval until the next write.
- `pins approve` requires `--digest` (the full observed digest `pins diff` printed; for `--all`, a review digest over the upstream's whole pending set) and refuses on any mismatch, checked in the same locked transaction as the promotion; it is mandatory, not optional, and prefixes are refused — an upstream that sees its change quarantined could otherwise swap to a second definition between the operator's diff and approve and get the unseen one pinned; an optional check would leave the unsafe path as the default, and a 12-hex prefix is only 48 bits of second-preimage resistance — operators must copy a 71-character digest (diff prints the exact command), and scripts that approved blindly now fail with exit 2.
- first contact is trust-on-first-use, with the poisoning lint run over every first-seen definition and new tools on known upstreams quarantined by default — the only automatic option that does not require a pre-built allowlist — a server malicious from day one is pinned; operators should review `mcpgate catalog` output before exposing it.
- the poisoning lint reports and never blocks — regex heuristics have false positives; blocking on them would make the gateway flaky — an operator who ignores alerts gets no protection from it.
- rate limit is checked before schema validation, and both client and tool buckets are checked before either is debited — invalid-argument loops still spend budget; rejected calls never do — a legitimate client that sends many invalid calls is throttled like any other.
- audit arguments default to `digest` (hash + top-level keys); demo uses `redacted` for readability — least data retained by default — investigators need the `redacted`/`full` mode configured *before* an incident to see values.
- audit integrity is a hash chain over canonical JSON with an optional externally anchored head, not signatures — detects edits/reorders/deletions with zero key management — an attacker with file write access can rewrite the whole chain; tail truncation needs `--expect-head`.
- implement RFC 8785 canonical JSON in-repo instead of adding a dependency — tiny surface, full control over the float/depth edge cases, both sides of every comparison are produced by the same code — exotic floats may differ from other JCS implementations (documented in docs/ARCHITECTURE.md).
- upstream liveness is a periodic `tools/list` re-listing (heartbeat, default 15 s) instead of `ping` — `ping` is gone from the 2026-07-28 stateless protocol and re-listing doubles as a continuous pin check — one extra listing per upstream every 15 s.
- the gateway advertises `tools.listChanged: false` and does not push catalog changes to connected clients — keeps the stateless HTTP path simple; clients re-list per session — a long-lived client keeps a stale catalog until it re-lists (calls to quarantined tools are still refused).
- tests use the SDK's in-memory `Client(server)` transport for gateway logic and real subprocesses on 127.0.0.1 for the integration tier, both inside `make check` — they run in ~15 s with no network/Docker, so there is no reason to split them out — CI runners that forbid loopback sockets would fail the integration tier.
- the agent demo uses Ollama `llama3.1:8b` when reachable and otherwise a deterministic scripted provider; tests only use the scripted provider and a fake HTTP transport for the Ollama mapping — contract forbids real models in tests and the demo must run offline — README shows both a real-model and a scripted transcript; the real model's behaviour varies run to run.
- no `DATA.md` datasets — all data are a handful of synthetic SKUs and notes defined inline in the sample servers — nothing external to license — n/a.
